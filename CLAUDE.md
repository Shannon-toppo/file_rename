# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This folder holds **consumer scripts for the `mv2title` library** (which lives in the sibling `../mv2title/` package and is its own git repo — this folder is *not* part of that repo). The scripts take real audio files, infer a clean song title with `mv2title`, and write it into the file's metadata.

- **`core.py`** — GUI-agnostic shared core (never prints): loads the connection `.env` (`find_env_file()`; dev = `../mv2title/.env`), defines `Track`/`Status`, and implements `download_tracks` (yt-dlp, progress callback + **`on_stage` post-download stage callback** + cancel `threading.Event`), `fetch_metadata` (metadata only, **no download** — flat playlist extraction, returns `filepath=None` QUEUED rows), `infer_titles` (batched, protects `manual=True` rows unless `force=True`), `write_tags` (skip policy lives here), `write_title`, `describe_result`, `read_url_list` (txt URL-list parsing — blank/`#` lines ignored — shared by `download.py -a` and the GUI).
- **`rename.py`** — thin CLI: scans `files/` for audio, then `core.infer_titles` + `core.write_tags`.
- **`download.py`** — thin CLI: `core.download_tracks` per URL (channel name rides along as an artist hint), then infer + write via core.
- **`gui/`** — PySide6 GUI (table-based) on top of `core.py`. See the GUI section below.
- **`files/`** — working directory for audio files (`.mp3`, `.wav`, `.m4a`).
- **`run_gui.py` / `selftest.py` / `file_rename_gui.spec` / `build.ps1` / `build.sh` / `.env.example` / `README_dist.md`** — PyInstaller packaging (`selftest.py` = the `--selftest` diagnostic). See the Packaging section below.
- **`ytdlp_runtime.py`** — fetches / updates / loads yt-dlp **and its EJS companion (`yt-dlp-ejs`)** at **runtime**; neither is bundled in the frozen build. See the Packaging section.

## How it wires to mv2title

Dependencies are declared in this folder's own `pyproject.toml` (uv-managed, `package = false`): **mutagen**, **yt-dlp**, **python-dotenv**, and **mv2title as an editable path dependency** (`[tool.uv.sources] mv2title = { path = "../mv2title", editable = true }`). Run `uv sync` here to create the venv — no `sys.path` manipulation anywhere.

- `core.py` loads `.env` at import via `find_env_file()` — search order ① `app_dir()/.env` (frozen: next to the exe / `.app`) → ② `../mv2title/.env` (dev fallback) — so `BASE_URL`/`API_KEY`/`MODEL`/`SYSTEM_PROMPT` (`ENV_KEYS`) are on `os.environ` before `Config.from_env()` reads them. `app_dir()` is frozen-aware (`sys.frozen`; on mac it resolves out of the `.app` bundle to its parent dir) and `FILES_DIR = app_dir()/"files"`. `apply_env_overrides()` layers GUI-settings overrides on top (priority: override > process env — `_PROCESS_ENV` snapshot taken before load_dotenv > `.env`; an empty override restores the default, keys absent everywhere are removed). `_augment_path_darwin()` (import-time) appends `_DARWIN_EXTRA_PATHS` — `/opt/homebrew/bin`, `/usr/local/bin`, and `~/.deno/bin` (expanded; deno's official-installer location) — to PATH on macOS because Finder-launched apps don't inherit the shell PATH (ffmpeg / deno detection); non-existent entries are appended anyway rather than probed, so the behaviour doesn't vary per machine (tests would too). Don't duplicate env setup in new scripts; import `core` instead.
- Inference uses the mv2title 0.3.0 API: `client = LLMClient(Config.from_env())` (wrapped in `core.make_client()`) and `extract_titles(inputs, client, batch_size=5, bypass_check=True)` with `TitleInput(stem, channel=...)` items; results are `TitleResult` objects (`.title` / `.valid`).
- `core.download_tracks` extracts `entry["channel"]` (falling back to `entry["uploader"]`) from yt-dlp into `Track.channel`, so the LLM prompt gets a `[チャンネル名]` artist hint.

## Pipeline specifics

- `bypass_check=True` means results are returned even if validation fails (no in-library retry/raise), so core **guards itself**: `infer_titles` raises `CoreError` (marking all targets `ERROR`) on `len(results) != len(targets)` to avoid mis-assigning titles (results are returned in input order, matched positionally). `write_tags` skips `valid=False` and empty-title rows — except `manual=True` rows, which are written on the user's authority.
- `write_title` is format-specific: `TIT2` frame for `.mp3`/`.wav` (mutagen ID3), `\xa9nam` atom for `.m4a` (MP4); other extensions raise `ValueError`. `SUPPORTED_EXTS` / `download.py`'s `--format` choices are limited to these three.
- `download_tracks` can pass audio filters to ffmpeg via `postprocessor_args` (`-af`): **loudness normalization** (`normalize=True` default; target `I` comes from the `loudness` arg, default `NORMALIZE_TARGET_I` = -14 LUFS, TP/LRA fixed — see `loudnorm_filter()`) and **experimental trailing-silence removal** (`trim_silence=True`, default OFF; `TRIM_SILENCE_FILTER` = areverse→silenceremove→areverse, conservative: only ≤ -50dB counts as silence and 1 s is kept so fade-outs survive). Silence trim runs **before** loudnorm so loudness is measured on the trimmed body. CLI flags: `--no-normalize` / `--loudness` / `--trim-silence`.
- **After the bytes arrive, `download_tracks` is still busy for a while** and yt-dlp's `progress_hooks` go silent there (they only fire on `status == "downloading"`), which made the GUI look frozen at "DL中 100%". Two stages live in that gap: yt-dlp's `FFmpegExtractAudio` postprocessor (a full re-encode carrying the `-af` chain — `areverse,silenceremove,areverse` buffers the whole decoded stream **twice**, so silence-trim ON is by far the slowest part), then `_fetch_localized_title` per video (a POST to YouTube's innertube `next` API, 5 s timeout each). `on_stage(Status)` reports both — `Status.CONVERTING` from a `postprocessor_hooks` hook on `status == "started"`, `Status.FETCHING` before the entries loop. That hook deliberately **does not raise on cancel** (unlike the download hook): killing ffmpeg mid-write would leave a truncated file, so cancellation takes effect at the re-check after `extract_info` returns.

## Running

- `uv sync` — once, to create the venv with all dependencies.
- `uv run python rename.py` — tags everything in `files/`.
- `uv run python download.py <URL> [-f mp3|wav|m4a]` — single URL (default format `mp3`).
- `uv run python download.py -a urls.txt [-f ...]` — one URL per line (blank lines and `#` comments ignored).
- A playlist URL downloads all entries; a `watch?v=...&list=...` URL downloads only the single video (`noplaylist=True`). Failed playlist entries are skipped (`ignoreerrors=True`).

## GUI (`gui/`)

A PySide6 table UI that runs the full **URL → download → infer → write** flow (plus manual correction). Launch with `uv run python -m gui`. It is a thin view over `core.py`; the GUI never re-implements pipeline logic.

- **Structure**: `__main__.py` (QApplication + MainWindow), `model.py` (`TrackTableModel`, a `QAbstractTableModel`), `workers.py` (`PipelineWorker` as a `QRunnable` + `WorkerSignals`), `main_window.py` (`MainWindow`), `i18n.py` (Qt 標準文言の日本語化).
- **Japanese Qt strings**: `gui/i18n.py`'s `install_qt_translators(app)` (called right after `QApplication(...)` in `__main__.main()`) loads Qt's own **`qtbase_ja.qm`**, without which the text-box right-click menu (Undo/Cut/Copy/Paste/Select All) and dialog buttons stay English — those strings belong to Qt, not to us, so translating them means shipping the catalog, not writing menu code. Lookup order is `QLibraryInfo(TranslationsPath)` then `PySide6/Qt/translations` (the frozen-build fallback); missing catalog = silently English.
- **Threading contract (strict — spelled out in `workers.py`'s docstring)**: one pipeline at a time (`QThreadPool.globalInstance()`; MainWindow disables the run buttons while running). The worker **never touches QWidgets or the model** — it calls `core` functions, mutates `Track` dataclass fields, and emits signals. All model updates happen in MainWindow slots on the **main thread** via **queued connections** (`track_updated` → `model.refresh_track`, `tracks_ready` → `model.replace_track`, `progress` → `model.set_percent`, plus `error`/`finished`). UI reads a `Track` only after receiving its signal (relying on the queued-connection happens-before). Cancellation is a `threading.Event` (`set()` by the stop button, passed to `core.download_tracks`; infer/write check it at stage boundaries and raise `CancelledError`). **`MODE_FULL` downloads up to `max_downloads` URL rows at once** — `_download_all` runs `_download_one` on a `ThreadPoolExecutor` (default `core.MAX_DOWNLOADS` = 2, settable in 設定). This exists because yt-dlp serializes receive → ffmpeg convert → next *within* one call and offers no way to background its postprocessors (its only concurrency flag, `--concurrent-fragments`, splits a single video), so without crossing rows the link sits idle through every conversion; a playlist entered as one row is still serial inside yt-dlp (expand it with [情報取得] first). Table order survives because `replace_track` finds the placeholder by identity and swaps it in place. `_download_one` swallows its own exceptions and returns `True`/`False`/`None` (cancelled) so the caller can count the stage summary without a lock; only `publish()` (append to `ready` + hand off to the infer stage) is serialized, and `core.ensure_ytdlp()` takes a lock so a first-use race can't have two threads editing `sys.path`. **`MODE_FULL` also runs DL and inference concurrently** — `_InferStage` (workers.py) owns one extra thread (`ThreadPoolExecutor(max_workers=1)`, so the LLM never sees two requests at once) and `_download_all(on_ready=stage.feed)` hands it each finished row; once `batch_size` inferable rows have piled up, that chunk goes to `core.infer_titles` (+ `core.write_tags` when auto-write is on) **while the remaining URLs keep downloading**. The leftover < `batch_size` rows are flushed in `close()`, so a run shorter than one batch behaves exactly as the old serial path did. Ownership of a `Track` moves DL-thread → infer-thread at `feed()` and never comes back, so no row is touched by both; `tracks_ready` is emitted *before* `feed()`, and the posted-event queue is FIFO, so the model always sees the row before its first `track_updated`. `_write_tracks` (no emit) is split out of `_run_write` so per-batch writes accumulate into **one** `write_summary` at the end. An inference failure records the first exception, stops further batch submission (so a dead LLM doesn't fail once per row), lets the downloads finish, and is re-raised on the worker thread afterwards → the usual `error` signal.
- **Row lifecycle**: adding a URL inserts a placeholder `Track` (`stem=url`, `url=url`, `status=QUEUED`) immediately; on download completion `tracks_ready` replaces that placeholder with the real `Track` row(s) (a playlist expands to several rows). Inference batches `QUEUED`/`PENDING`, non-`manual` rows into `core.infer_titles` calls of `batch_size` rows (never per-row) — in `MODE_FULL` fed incrementally as downloads finish (see the threading contract above), in `MODE_INFER` as one call over the selection. Auto-write ON → `core.write_tags`; OFF → stops at `PENDING`. The [情報取得] button runs `MODE_FETCH` (`core.fetch_metadata`, rows show `Status.FETCHING` with the busy-blue tint): it expands **only untouched placeholder rows (`stem == url`, no `filepath`)** into metadata rows (title/channel, still `filepath=None`/QUEUED — a later 実行 downloads them normally) without downloading, for inspecting large playlists first; already-expanded and local rows are skipped, so re-running never overwrites manual edits. When a fetched row is later downloaded, `_download_all` **carries over manual edits (title → `manual`/`valid`/`PENDING`, and artist)** onto the real `Track` before `tracks_ready` — single-track results only (a playlist expansion can't be mapped back to one row's edits). URL lists come in via the [リスト読込] button, a **`.txt` drop** onto the table, or **Ctrl+Enter in the URL box** (an eventFilter on `_url_edit` — not a QShortcut — so tests can drive it without focus). Local-file adds ([ファイル追加] / [保存先から取り込み] / audio-file drop — all through `MainWindow.add_files`) **skip files already in the table** (resolved-`filepath` comparison, within the batch too), so pressing 取り込み repeatedly never duplicates rows; [保存先から取り込み] scans `self._out_dir or core.FILES_DIR` (follows the settings dialog's save-dir, not a hardcoded FILES_DIR). An empty table paints a hint text (`_DropTableView.paintEvent`) advertising the URL→追加→実行 flow and drag&drop.
- **Model specifics**: columns `#` / 元タイトル(stem) / チャンネル / 推定タイトル / アーティスト / 状態 / 形式. Title and artist columns are editable (`EDITABLE_COLUMNS`); `setData` on the title column (delegating to `set_title`) sets `guessed_title`, `manual=True`, `status=PENDING`, and manual rows render with a `✎ ` prefix. The artist column (`set_artist`) is **never inferred** — typed manually or bulk-filled from `Track.channel` via the [チャンネル名→アーティスト] button (undoable macro); editing it doesn't touch `manual`, but flips `DONE` rows back to `PENDING` so they get rewritten (`core.write_title` writes `TPE1`/`©ART` only when artist is non-empty). After any write, the worker emits `write_summary(done, skipped, errors)` shown in the status bar; fetch/download stages likewise emit `stage_summary(stage, done, errors)` (only when ≥1 row was attempted) so failures don't drown in a final「完了」. ERROR rows display `track.error` in the 推定タイトル column (DisplayRole only — EditRole stays the raw `guessed_title`), and the context menu has「エラー行を再試行待ちに戻す」→ `model.reset_error(row)` (ERROR → PENDING if it has a title, else QUEUED; re-processing rides the normal 実行/書き込み buttons, no worker is started). Playlist downloads show "DL中 2/5 45%" (yt-dlp `playlist_index`/`n_entries` flow through `on_progress` → the `progress` signal's label arg → the percent dict's `(percent, label)` tuple); once the bytes are in, the row flips to `CONVERTING` and shows "変換中 2/5" — number only, since that stage reports no percent. `clear_title(row)` resets a row (empty title / `manual=False` / `valid=None` / `QUEUED`) for re-inference. `sort(column, order)` reorders `self._tracks` in place (no `QSortFilterProxyModel`; `#` column is a no-op, percent dict cleared). Download percent lives in a `row→percent` dict inside the model (no display field added to `Track`). Background colors: DONE=green / ERROR=red / PENDING+`valid is False`=yellow / FETCHING·DOWNLOADING·CONVERTING·INFERRING=blue; tinted rows also force a dark `ForegroundRole` (OS dark themes default to white text, unreadable on pastels). While DOWNLOADING, the status column exposes `PERCENT_ROLE` and `_ProgressDelegate` (in `main_window.py`) paints a determinate progress bar instead of text.
- **Excel-style ops (phase 4)**: `gui/clipboard.py` (`selection_to_tsv` / `resolve_paste_targets` — pure, unit-tested) drives `Ctrl+C`/`Ctrl+V` (TSV, title column only on paste); `gui/commands.py` has `QUndoCommand` subclasses (`EditTitleCommand` / `ClearTitleCommand`) so **all UI title edits route through a `QUndoStack`** (`Ctrl+Z`/`Ctrl+Y`; paste is one macro). The title-column edit delegate (`_UndoEditDelegate`) pushes a command instead of calling `setData`, avoiding double-apply. Right-click menu (`build_context_menu`), header-click sort (disabled while running; clearing a non-empty undo stack via `_clear_undo_history` posts a status-bar notice unless a pipeline is running), and `QSettings("mv2title", "file_rename_gui")` window/column/toggle persistence (`closeEvent`; skipped when `MainWindow(restore_settings=False)`). Tests create MainWindow via a `main_window` fixture that closes+deletes it (multiple undestroyed `QMainWindow`s crash pytest-qt's event processing on Windows).
- **Fill handle (Excel 風ドラッグコピー)**: `_DropTableView` paints a small square at the bottom-right of the selection when the **current cell is in an editable column** (`EDITABLE_COLUMNS` = 推定タイトル / アーティスト); dragging it up/down copies the source value(s) into the swept rows. `fill_anchor()` returns `(col, top, bottom)` — the contiguous selected-row range when it contains the current row, else just the current row — and `mousePress/Move/Release` on the handle bypass the view's own selection/edit handling (a plain click there must not start an edit). The actual write is `MainWindow.fill_from_handle(col, top, bottom, target)`: multi-row sources repeat as a pattern (upward drags map from the bottom of the source), everything lands in one `フィルコピー` undo macro via `push_edit`, and it no-ops while a pipeline runs (`set_fill_enabled(False)` from `_set_running` also hides the handle).
- **Selection visibility**: the view gets an explicit palette with the same `Highlight`/`HighlightedText` for **Active and Inactive** color groups. Qt's default Inactive highlight is a pale gray that is nearly invisible on top of the status tint colors (green/yellow/red), so pressing any button — which moves focus off the table — made selections look cleared. Row adds (`add_urls` / `add_files`) end with `select_all_rows()`, so a freshly added batch is immediately actionable by the 選択行 buttons instead of erroring with「行が選択されていません」.
- **Robustness (phase 5)**: `core.check_connection()` does a lightweight `GET {BASE_URL}/models` via `urllib` (3 s timeout, no LLM completion) **and validates the body is an OpenAI-style models list (`"data"` array)** — HTTP status alone is not trusted because LM Studio answers 200 with an error JSON on any unknown path (e.g. a BASE_URL missing `/v1`), which made the 接続テスト a false positive — and additionally **cross-checks `Config.from_env().model` against the returned `data[].id` set**: an unknown model stays OK but the message carries a 注意 (LM Studio may alias-resolve, so it's a warning, not a failure). The comparison goes through **`core._model_aliases()`** (lowercase, drop an `@quant` suffix, and also match the part after the last `/`) — LM Studio lists ids with a publisher prefix (`google/gemma-4-e2b`) while its own UI/config shows the bare name, so exact matching mis-warned about models that infer fine. `PipelineWorker` calls it at the start of `MODE_FULL` and **degrades to download-only** (`connection_failed` signal, rows stay `QUEUED`) when the endpoint is unreachable; `skip_infer=True` forces this; MainWindow surfaces the degradation as a **dismissable yellow banner above the table** (`_banner`, fixed dark-on-yellow stylesheet, auto-hidden on the next `_set_running(True)`) in addition to the status bar. The **yt-dlp group** in 設定 shows `<yt-dlp 版> ／ EJS <版>` (or `EJS 未取得` — missing EJS is invisible otherwise since downloads still run), and [更新] fetches the pair; [更新を確認] reports a missing EJS even when the body is current. `MainWindow._check_ytdlp()` asks at startup — for yt-dlp when it's absent, otherwise for EJS when `_ejs_missing()` (compares the installed EJS against the METADATA pin; a dev venv with no extracted tree is never "missing") — one dialog at most, and `YtdlpWorker` reports `needs_restart` from `core.YoutubeDL is not None` because yt-dlp decides whether EJS exists at import time. `gui/settings_dialog.py` is grouped into three `QGroupBox`es — ダウンロード (out_dir / default format / **同時ダウンロード数 (1-4, `options/max_downloads`, default `core.MAX_DOWNLOADS` = 2)** / playlist expansion / normalize + its 基準値 (LUFS spinbox, disabled while normalize is OFF) / trailing-silence trim (試験的)), タイトル推定 (LLM) (batch size / auto-write default / **LLM connection overrides** + 接続テスト), 表示 (theme / log level) — with `setMinimumWidth(560)` + `ExpandingFieldsGrow` (the mac style otherwise centers fields at sizeHint width, truncating paths/URLs). Connection overrides: BASE_URL / API_KEY (password echo) / MODEL / SYSTEM_PROMPT — empty field = use the `.env` value shown as placeholder via `core.env_defaults()`; **an unset MODEL's placeholder shows the effective fallback `core.DEFAULT_MODEL`** (re-exported from `mv2title.connect` — the library silently defaults, so "未設定" alone would misstate what gets sent); returned as `values()["llm_overrides"]` with `ENV_KEYS` keys, applied through `core.apply_env_overrides()` on startup + apply_settings, persisted as `options/llm_*` — API key is plaintext in QSettings, personal-use tradeoff. All persisted via `QSettings`; the connection-test button temporarily applies the dialog's values and restores `os.environ` after (success shows core's message as-is; only failures get an "NG: " prefix). `gui/logpanel.py` has `QtLogHandler(QObject, logging.Handler)` which **only emits a signal** (handlers run on worker threads — never touch widgets there); `LogPanel` receives it via a queued connection; attached to the `mv2title`/`core`/`yt_dlp` loggers and detached in `closeEvent`. **yt-dlp** doesn't use `logging` (it prints to stdout), so `PipelineWorker` passes `logger=logging.getLogger("yt_dlp")` (with `quiet=True`) into `core.download_tracks` to route its output through logging — GUI DLs thus show in the log panel. **Level filtering is done in one place — on the handler** (`handler.setLevel`, default WARNING, chosen via the [設定] ログレベル combo, `LOG_LEVELS` / `options/log_level` persisted); the target loggers themselves are set to DEBUG in `attach_handler` so records reach the handler. Missing ffmpeg **or deno** → startup status-bar warning (one line listing every missing tool — `_check_external_tools()`, so neither can bury the other) **plus a `QMessageBox.warning` per tool with OS-specific install hints (`_ffmpeg_install_hint` / `_deno_install_hint`), and `_confirm_ffmpeg()` / `_confirm_deno()` ask before 実行 (Yes/No; ffmpeg defaults No, deno defaults Yes)** — both modals are suppressed when `_settings is None` (i.e. `restore_settings=False`, the test mode) so offscreen tests never block.
- **Preview playback**: `gui/player.py` `PreviewPlayer` wraps `QMediaPlayer`/`QAudioOutput` (QtMultimedia, part of the `pyside6` metapackage); the real player is **lazily created on first `play()`** so tests/offscreen never touch the multimedia backend. A control row between the table and the bottom buttons has [▶/⏸] + a seek `QSlider` + a `m:ss / m:ss` time label (`format_time`) + [♪ 末尾試聴]. [▶] plays the first selected row that has a `filepath`; pressing it again on the **same file** pauses/resumes (`current_path` comparison — it does not restart), selecting another row switches files. The slider follows `position_changed`/`duration_changed` (not updated while the user drags: `isSliderDown()`), and `sliderMoved` → `seek()`; its range keeps a floor of 1 (`setRange(0, max(1, duration))`, initial `(0, 1)`) because a `(0,0)` range makes macOS draw no groove at all — the idle control looked like empty space. [♪ 末尾試聴] plays only the last `TAIL_SECS` (10 s) to check the silence trim — the tail seek waits for `durationChanged` because duration is unknown right after `setSource`. Preview is stopped and the controls disabled while a pipeline runs (`_set_running`), and stopped on `closeEvent`.
- **Tests**: fully offline. `tests/conftest.py` sets `QT_QPA_PLATFORM=offscreen` before any Qt import. `test_gui_model.py` covers columns/editability/manual prefix/colors/CRUD + a MainWindow smoke test; `test_gui_player.py` covers preview wiring with a fake player (real `QMediaPlayer` is never constructed); `test_gui_i18n.py` asserts `qtbase_ja.qm` loads and a `QLineEdit` context menu comes out Japanese (translators are removed again so other tests aren't affected); `test_gui_excel.py` also covers the fill handle (anchor rules, pattern repeat, undo macro, running guard, plus one real press→move→release drag); `test_gui_workers.py` monkeypatches `core.download_tracks`/`infer_titles`/`write_tags` and uses `qtbot.waitSignal` to verify the pipeline (auto-write, pending stop, per-row error isolation, cancellation, force re-infer, degraded mode) — an **autouse fixture stubs `core.check_connection`** so `MODE_FULL` never hits the network; when adding fakes for `core.download_tracks`, keep the signature in sync (`out_dir=None` included) or the worker's per-row `except` will silently absorb the `TypeError`. **Every test that constructs a `MainWindow` must pass `restore_settings=False`** (test mode: no real-QSettings pollution, and it suppresses the ffmpeg-missing modals — on CI runners without ffmpeg a default-args `MainWindow()` blocks on `QMessageBox` until the 6-hour job timeout; this once burned the whole monthly Actions quota). Guardrails: `pytest-timeout` (dev dep, `timeout = 60` per test in `pyproject.toml`) and `timeout-minutes: 15` on the CI job. Run everything with `uv run pytest tests/ -q`.

## Packaging (PyInstaller)

The GUI ships as a **onedir** build: Windows `dist/FileRenameGUI/` (exe) and macOS `dist/FileRenameGUI.app` (Apple Silicon). **Neither ffmpeg nor yt-dlp is bundled** — ffmpeg is installed by the user (winget / brew; the app warns at startup and before 実行, see GUI section), and yt-dlp is fetched at runtime by `ytdlp_runtime` (see below).

- **Build**: `./build.ps1` (Windows) / `./build.sh` (mac) → `uv sync` + `uv run pyinstaller file_rename_gui.spec --noconfirm`, then copies `.env.example` + `README_dist.md` into `dist/`. PyInstaller can't cross-compile — the mac build runs on a mac with the same sibling layout (`../mv2title` editable dep). `pyinstaller` is in the dev dependency group.
- **`file_rename_gui.spec`** is one cross-platform file: entry point `run_gui.py` (PyInstaller can't take `-m gui`), `hiddenimports=["PySide6.QtMultimedia"]` (lazy import in `gui/player.py`; yt-dlp ships its own hook, which still runs — see the strip below), `datas` carrying **`qtbase_ja.qm` → `PySide6/Qt/translations`** (the PySide6 hook doesn't bring translations along, and without it the frozen app's text-box context menus revert to English), `console=False`, and a `BUNDLE(...)` block under `sys.platform == "darwin"` (no `codesign_identity` → PyInstaller ad-hoc-signs on arm64; personal distribution, no notarization — recipients use right-click→開く or `xattr -cr`). `build.sh` zips the .app with `ditto -c -k --keepParent` to preserve attributes.
- **Frozen-path rules**: never use `__file__`-relative paths for user-facing files — go through `core.app_dir()` / `core.find_env_file()` (see the wiring section). The distributed `.env` lives **next to the exe / .app**, not inside `_internal`.
- **yt-dlp is NOT bundled** — it goes stale within months (YouTube's signature / n-challenge changes make every download 403), and baking it into the PYZ meant rebuilding and redistributing the exe each time. `ytdlp_runtime.py` instead downloads the PyPI **wheel** (`py3-none-any`, zero mandatory deps — all extras) with `urllib` + `zipfile` (no pip) and extracts it to a **version-named** directory under the per-user data dir (`%LOCALAPPDATA%/FileRenameGUI/runtime/<version>/`, mac `~/Library/Application Support/...`); a pre-seeded `core.app_dir()/runtime` wins if present (offline distribution). Version dirs are never overwritten in place — install extracts to `.staging-*` and `rename`s, so a failed fetch can't break the working copy, and `prune()` keeps 2 generations for rollback. The per-user dir (not next to the exe) is deliberate: macOS **App Translocation** runs a quarantined `.app` from a read-only random path, so "next to the app" isn't reliably writable. `core.YoutubeDL` starts as `None` and `core.ensure_ytdlp()` fills it on first use — it **returns early when already set**, which is what keeps `monkeypatch.setattr(core, "YoutubeDL", FakeYDL)` in the tests from touching `sys.path` or the network.
- **EJS (`yt-dlp-ejs`) rides along with yt-dlp** — the JS that solves YouTube's signature / n challenges does not live in yt-dlp itself. Without it yt-dlp warns `Signature solving failed` / `n challenge solving failed` and wants to fetch the scripts per-run from GitHub or npm (`--remote-components ejs:github` / `ejs:npm`), which is disabled by default. `ytdlp_runtime.install_ejs(target)` instead extracts the `yt-dlp-ejs` wheel **into the same version directory as yt-dlp**, which keeps one `sys.path` entry, pins the pair together, and lets `prune()` drop both generations as a unit. The version is **not** "latest": `required_ejs_version()` reads the exact pin out of the downloaded yt-dlp's own `yt_dlp-*.dist-info/METADATA` (`Requires-Dist: yt-dlp-ejs==X`), because yt-dlp verifies the script against a vendored hash list and rejects a mismatched major.minor — a wrong version is as good as no EJS. The package route is preferred over `remote_components` deliberately: it is the highest-priority script source (`ScriptSource.PYPACKAGE`), it is hash-checked by yt-dlp, and it means downloads never reach out to github.com/npm at run time. Swap of an existing EJS goes through a staging dir and rolls the old tree back on failure; a failed EJS fetch never fails the yt-dlp update itself (downloads still work, just degraded).
- The spec's `_strip_ytdlp` covers **both** `yt_dlp` and `yt_dlp_ejs`, and matches **module names (`pkg.`) and data paths (`pkg/`, `pkg\\`)** — `a.datas` carries `yt_dlp_ejs/yt/solver/*.min.js` under path-style names, so a dot-only filter leaves the JS behind (and a data-only `yt_dlp_ejs/` directory in `_MEIPASS` can still be imported as a namespace package, shadowing nothing today but a trap). Bundling EJS would be actively harmful: the PYZ resolves before `sys.path`, so a frozen copy would hide the runtime-installed matching version.
- **`--selftest` (diagnostic)** — `run_gui.py` dispatches `--selftest` to `selftest.py` before any Qt import, so a frozen build can be checked from a terminal (`console=False` means the GUI build otherwise prints nowhere): it lists frozen-ness / `app_dir()` / `.env` / `FILES_DIR`, finds ffmpeg + deno, loads the runtime yt-dlp, and does an HTTPS GET to PyPI (the frozen TLS path — the classic thing that only breaks after packaging). `--update` runs the same fetch/update as the 設定 dialog (terminal fallback when the GUI can't be driven), `--download <URL>` pulls one track into a temp dir and deletes it (proves yt-dlp → deno → ffmpeg subprocesses work from inside the bundle). Labels are padded by **display width** (`unicodedata.east_asian_width`), not character count, or the Japanese labels misalign. On macOS run `FileRenameGUI.app/Contents/MacOS/FileRenameGUI --selftest`; on Windows the GUI-subsystem exe has no console, so redirect: `FileRenameGUI.exe --selftest > log.txt`.
- **macOS build verified** (2026-08-28, macOS 26.6 / Apple Silicon): fetch → load → metadata → download → mp3 all pass from the frozen `.app` (`--selftest --update --download`, incl. a fresh install with `HOME` pointed at an empty dir). PyInstaller's mac bootloader sets **no `DYLD_LIBRARY_PATH`** (checked with `ps eww` on the running app), so the ffmpeg/deno subprocesses aren't at risk of loading the bundle's dylibs.
- **The spec must NOT `excludes=["yt_dlp"]`** — that stops the analysis from walking yt-dlp's imports, so stdlib modules only it needs (`optparse` first, then more) never get collected and the external yt-dlp dies with `ModuleNotFoundError`. Let the analysis run, then drop the collected `yt_dlp.*` entries from `a.pure` / `a.datas` (`_strip_ytdlp` in the spec). Measured: PYZ 14.7MB → 9.3MB, exe 15.0MB → 9.7MB, 1043 modules removed. yt-dlp therefore stays a **runtime dependency in `pyproject.toml`** — the build needs it installed for the analysis, and it's the dev fallback when no runtime dir exists.
- **A JS runtime (deno) is effectively required** for YouTube: without one yt-dlp still downloads but the n-challenge goes unsolved and throughput collapses (measured 1.7 MiB/s vs 12–32 MiB/s), plus yt-dlp warns the path is deprecated. Checked at startup and before 実行 exactly like ffmpeg (`_check_external_tools()` / `_confirm_deno()` / `_deno_install_hint()`), except the pre-run dialog defaults to **Yes** — unlike ffmpeg, a missing deno degrades speed rather than breaking the output. Only `deno` is probed: it is the only runtime yt-dlp enables by default (a `node` on PATH is not used without `--js-runtimes`).
- `build/` and `dist/` are gitignored; the `.spec` is committed.

## Dependencies / gotchas

- **ffmpeg on PATH** is still required for `download.py`'s mp3/wav conversion (not pip-installable).
- **`yt-dlp-ejs`** is declared in `pyproject.toml` next to `yt-dlp` for the same two reasons: the dev venv fallback (no extracted runtime dir → plain `import`) and PyInstaller's analysis. The frozen build strips both.
- Requires a running OpenAI-compatible LLM endpoint configured via `.env` (dev: `../mv2title/.env`; see that package's CLAUDE.md) or the GUI 設定 dialog overrides.
- Indentation here is **4 spaces** (unlike the mv2title package, which uses tabs); comments/docstrings are Japanese.
